⚑ MODE-AWARE DERIVATION (confirmed this round):
Text tier meaning (darkest -> lightest) is fixed: Color1 is always the anchor 
the user picks, Color2 is always the middle tier, Color3 is always the most 
extreme tier — but which DIRECTION "extreme" points depends on preset mode:

  LIGHT MODE presets (typically dark text on light background):
    --page-text-1 = darkest  (user-picked, the anchor)
    --page-text-2 = middle   (lightened from Color1)
    --page-text-3 = lightest (lightened further from Color1)

  DARK MODE presets (typically light text on dark background):
    --page-text-1 = lightest (user-picked, the anchor)
    --page-text-2 = middle   (darkened from Color1)
    --page-text-3 = darkest  (darkened further from Color1)

Same tier percentages in both directions (20% / 70%), only the mix target 
changes (white vs. black). Implementation must be scoped per mode class, 
matching the existing :root/.mode-light vs .mode-dark pattern already used 
elsewhere in the codebase:

  :root, .mode-light {
    --page-text-2: color-mix(in srgb, var(--page-text-1) 80%, white 20%);
    --page-text-3: color-mix(in srgb, var(--page-text-1) 30%, white 70%);
  }
  .mode-dark {
    --page-text-2: color-mix(in srgb, var(--page-text-1) 80%, black 20%);
    --page-text-3: color-mix(in srgb, var(--page-text-1) 30%, black 70%);
  }

ASSUMPTION: percentages stay identical (20%/70%) in both directions — only 
the white/black mix target flips. If dark mode should use different 
percentages (darkening 20%/70% may read as too subtle or too harsh compared 
to lightening the same amount, depending on the anchor color), flag it and 
I'll adjust. Also note: every selector mapped to --page-text-2/--page-text-3 
in the SELECTOR LIST below is unaffected by this — the selector-to-tier 
mapping doesn't change, only how each tier's value is computed per mode.
